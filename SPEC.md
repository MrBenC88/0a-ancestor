# 0a-ancestor — Agent Setup Template Spec

Status: ready to implement · Owner: Ben · Updated: 2026-11-14

## 1. Summary

`0a-ancestor` is a **public template repo** that gives any `~/dev/` directory a complete agent and shell setup: shared agent rules, portable skills, reusable agents, a handoff protocol, token-saving scripts, and zsh config. At each new company: clone into `~/dev/`, rename the remote to `upstream`, run `bootstrap.sh`, fill in templates locally. **No real personal or company data is ever committed.**

### Goals

- **One instruction source** read by Claude Code, Codex, Copilot and Cursor.
- **Skill-first.** Any prompt or command that repeats becomes a skill by default.
- **Token efficiency is a hard constraint.** Always-loaded context stays small; everything else loads on demand.
- **Tool- and company-agnostic.** Works on day one whatever tools are approved.
- **Grows over time.** Starts with a solid core; aliases, skills and agents get added as needs show up.

### Non-goals

- Not a framework; no MCP server.
- No automated agent-to-agent orchestration yet (handoffs stay file-based).
- Never any company data, code or internal URLs.

## 3. Bootstrap

`bootstrap.sh` turns a fresh clone into a working setup. **Idempotent**: safe to re-run. `--check` prints status without changing anything. `--dry-run` prints what it would do. Never overwrites existing user files; on conflict it backs up to `*.bak.<timestamp>` and says so.

Steps:

1. Resolve `DEV_DIR` as the parent of the repo (default `~/dev`).
2. Symlink `~/dev/AGENTS.md` and `~/dev/CLAUDE.md` into the repo.
3. Link `skills/*` and `company/skills/*` into each tool's user-level skills dir that exists or is configured: `~/.claude/skills`, `~/.codex/skills`, `~/.agents/skills`.
4. Run `scripts/gen-agents` to write per-tool agent files from `agents/` and `company/agents/` (`~/.claude/agents/`, `~/.codex/agents/`).
5. Shell: append **one guarded line** to `~/.zshrc` if absent:
   `[ -f "$HOME/dev/0a-ancestor/shell/init.zsh" ] && source "$HOME/dev/0a-ancestor/shell/init.zsh"`
   Copy `shell/local.zsh.template` → `shell/local.zsh` if missing.
6. Company tag: if `COMPANY_TAG` isn't set in `shell/local.zsh`, prompt for it once (any short lowercase code) and save it there. Write the matching pattern to `.git/info/exclude`.
7. Copy `editor/.vscode` → `~/dev/.vscode` if missing; generate `~/dev/dev.code-workspace` from repos in `~/dev`.
8. Create `me/*.md` from templates and `handoff/` if missing.
9. Run `scripts/index-repos`.
10. Print a summary: linked / skipped / backed up / next manual steps.

Optional flag `--brew` runs `brew bundle --file=Brewfile`. Not run by default.

### Tool shims

| Tool | Reads | Shim |
| --- | --- | --- |
| Claude Code | CLAUDE.md | `CLAUDE.md` = `@AGENTS.md` + Claude-only notes |
| Codex | AGENTS.md | none |
| GitHub Copilot | AGENTS.md, `.github/copilot-instructions.md` | optional one-line pointer |
| Cursor | AGENTS.md, `.cursor/rules/` | none |

## 4. Shell setup (zsh)

### 4.1 Structure

`~/.zshrc` stays the user's own; it sources only `shell/init.zsh`, which sources the other files in order: `env → aliases → git → k8s → agents → functions → local`. Each file is small and themed. `local.zsh` (gitignored) holds company specifics: `COMPANY_TAG`, kube contexts, internal hostnames, tokens loaded from the keychain — **never committed**. Company-specific aliases also go here, named with the tag (e.g. `deploy-<company-tag>`).

Startup must stay fast: no network calls, no `brew --prefix` in hot paths, lazy-load heavy completions. Target: `init.zsh` adds < 50 ms (`time zsh -i -c exit`).

### 4.2 env.zsh

- `export DEV_DIR="$HOME/dev"`, `export ANCESTOR="$DEV_DIR/0a-ancestor"`
- Prepend `$ANCESTOR/scripts` to `PATH`.
- `EDITOR=code --wait` (overridable in local.zsh).

### 4.3 Navigation aliases and functions

| Name | Does |
| --- | --- |
| `gtd` | `cd $DEV_DIR` |
| `anc` | `cd $ANCESTOR` |
| `d <name>` | fuzzy jump to a repo in `$DEV_DIR` (fzf; exact match first) |
| `..`, `...` | up one / two dirs |
| `mkcd <dir>` | make dir and cd into it |
| `reload` | re-source `~/.zshrc` |
| `aliases` | list all aliases/functions defined by this repo, with one-line descriptions |

### 4.4 Git (git.zsh + scripts)

| Name | Does |
| --- | --- |
| `gpa` | **Pull all repos' default branches.** See 4.5. |
| `gst-all` | One line per repo: branch, dirty/clean, ahead/behind. |
| `gs` | `git status -sb` |
| `gco <branch>` / `gcb <branch>` | checkout / create branch |
| `gcm` | checkout the repo's default branch (detected, not hardcoded `main`) |
| `gup` | fetch + rebase current branch on origin default branch |
| `gp` / `gpf` | push / push `--force-with-lease` (never plain `--force`) |
| `gl` | pretty one-line log graph, last 20 |
| `gclean` | delete local branches already merged into default; `--dry-run` first |
| `gwip` / `gunwip` | quick WIP commit / undo it |
| `prc` | `gh pr create --fill` then open in browser |
| `prv` | `gh pr view --web` |
| `prs` | `gh pr status` |

### 4.5 `gpa` spec

For every git repo directly under `$DEV_DIR` (skip `0a-ancestor` unless `--all`):

1. Detect default branch: `git symbolic-ref refs/remotes/origin/HEAD`, fall back to `main`, then `master`.
2. `git fetch --prune origin` (parallel across repos, max 8 jobs).
3. If the current branch **is** the default and the tree is clean: `git pull --ff-only`.
4. If on another branch: fast-forward the local default branch without switching: `git fetch origin <def>:<def>` (only if it is a fast-forward).
5. Never stash, never switch branches, never merge. Dirty or diverged repos are **skipped and reported**.
6. Output: one line per repo — `✓ updated (3 commits)`, `= up to date`, `⚠ skipped: dirty`, `✗ diverged`. Summary counts at the end. Exit non-zero if any repo errored.

Flags: `--dry-run`, `--jobs N`, `--only <glob>`.

### 4.6 k8s.zsh (prod investigation helpers)

Read-only by default. Anything that mutates the cluster needs an explicit confirm prompt.

| Name | Does |
| --- | --- |
| `k` | `kubectl` |
| `kctx` / `kns` | switch context / namespace (fzf picker) |
| `kpods [ns]` | pods with status, restarts, age |
| `klogs <pod-or-label>` | tail logs (uses `stern` if installed) |
| `kev [ns]` | recent warning events, newest first |
| `k8s-summary` | script: unhealthy pods, restart counts, recent warnings — ≤ 40 lines |
| `logs-errors <source>` | script: recent error lines grouped by message, with counts |

### 4.7 agents.zsh

| Name | Does |
| --- | --- |
| `cc` | `claude` in current dir |
| `ccr` | `claude --resume` |
| `cx` | `codex` in current dir |
| `handoff` | print `LATEST.md` for the current repo's project |
| `wl "<text>"` | append a timestamped line to `me/worklog.md` |

### 4.8 Brewfile (initial)

`git gh jq yq fzf ripgrep fd bat eza zoxide kubectl k9s stern direnv shellcheck` plus the `iterm2` cask. iTerm2 runs on its defaults; no custom profiles. Optional commented lines for `jira-cli`.

## 6. Skills

### 6.1 Generalize-by-default rule (goes in root AGENTS.md, verbatim)

This is a **default behavior for every agent on every prompt**, not something the user has to ask for.

> After finishing any task, ask: is this reusable? If the prompt, command or procedure could recur, capture it — create a skill (a procedure) with `/create-skill` or an agent (a role) with `/create-agent` in the same session. Don't ask first; tell the user in one line what you added and where.
>
> Decide where it goes:
> - **Generic** (would work at any company): write it in generalized form, with no company names, URLs, project keys or internal tool names. Company values are read from `me/context.md` at runtime. Save to `skills/<name>/` or `agents/<name>.md`.
> - **Company-specific** (depends on internal tools, services or conventions): append `-<COMPANY_TAG>` to the name (e.g. `deploy-<company-tag>`, `oncall-<company-tag>`). Save to `company/skills/<name>-<tag>/` or `company/agents/<name>-<tag>.md`, which are never committed.
> - **Mixed:** split it — a generic skill plus a thin `-<tag>` skill that supplies the company specifics and calls the generic one.
>
> Before creating, check whether an existing skill or agent covers it. If one does, extend it instead of adding a near-duplicate.

`COMPANY_TAG` is a short lowercase code set once per company in `shell/local.zsh` and `me/context.md` (placeholder `<company-tag>`, chosen at setup). Agents read it from `me/context.md`.

| Situation | Name | Location |
| --- | --- | --- |
| Generic PR description procedure | `pr-create` | `skills/pr-create/` |
| The company's deploy pipeline steps | `deploy-<company-tag>` | `company/skills/deploy-<company-tag>/` |
| Generic incident flow + company dashboards | `prod-investigate` + `prod-investigate-<company-tag>` | `skills/` + `company/skills/` |
| Company on-call responder role | `oncall-<company-tag>` | `company/agents/` |

### 6.2 Format (open SKILL.md standard)

- Frontmatter: `name`, one-sentence `description` saying **when** to use it. Only this loads until invoked.
- Body ≤ ~150 lines. Long reference → `references/`. Deterministic steps → a script in `scripts/` that the skill calls.
- No hardcoded company values: read from `me/context.md`.
- Each skill ends with an **Output** section defining exactly what it returns (keeps responses short).

### 6.3 Starter skills

| Skill | Does |
| --- | --- |
| `create-skill` | Meta-skill: applies the generic/company rule (6.1), scaffolds the folder, writes the description, moves mechanical steps into a script, adds it to the index |
| `create-agent` | Same as `create-skill`, for agents: picks a tier, tools and output contract, then runs `gen-agents` |
| `handoff` | Writes or reads a handoff note (section 8) |
| `worklog` | Appends a summary of the session to `me/worklog.md` |
| `new-project` | Runs `scripts/new-project`, then fills `SPEC.md` with the user |
| `jira-read` | Fetch ticket(s) and summarize: goal, acceptance criteria, linked PRs, open questions |
| `jira-write` | Draft a ticket from context (title, description, AC, labels), show it, create only after confirm |
| `pr-create` | Branch check, conventional title, description from diff + SPEC/ticket, test plan; opens with `gh` |
| `pr-review` | Review a PR diff against AGENTS.md conventions; output findings ranked by severity |
| `prod-investigate` | Structured incident flow: symptom → scope → recent deploys → logs → k8s state → hypothesis → next check |
| `k8s-triage` | Wraps `k8s-summary`; interprets output, suggests next read-only command |
| `prod-logs` | Wraps `logs-errors`; groups, dedupes, links errors to code paths |
| `fe-best-practices` | Frontend conventions (React/Next perf, a11y, bundle size) for review and implementation |

Jira skills use whatever is available, in order: a Jira MCP connector → `jira-cli` → REST via `curl` with a token from the keychain. Never paste tokens into files.

## 7. Agents and model routing

### 7.1 Tiers

Agent files name a **tier**, not a model. `models.md` maps tiers to models, so a model change is a one-line edit.

| Tier | Use for | Claude | Codex |
| --- | --- | --- | --- |
| heavy | Planning, architecture, specs, final review, incident hypotheses | Opus 5.5 | Sol (high); Astra only by explicit escalation |
| standard | Scoped implementation from a plan | Opus 5.5, or Sonnet 5.5 to save tokens | Sol (medium) |
| light | Search, exploration, renames, test stubs, boilerplate, log scanning | Sonnet 5.5 or Haiku 5.5 | Luna (xhigh effort) |

Fable is excluded. Smaller models need higher effort settings, so light-tier Codex runs Luna at xhigh.

### 7.2 Starter agents

| Agent | Tier | Tools | Output |
| --- | --- | --- | --- |
| planner | heavy | read-only | SPEC.md draft + handoff note |
| implementer | standard | read/write | Code + handoff note |
| code-reviewer | heavy, fresh context | read-only | Ranked findings in the handoff note |
| explorer | light | read-only | Conclusions only, never file dumps |
| test-writer | light | read/write | Tests |
| prod-investigator | heavy (lead) + light (log/k8s scans) | read-only, no cluster mutations | Incident summary: timeline, evidence, hypothesis, next checks |
| pr-author | standard | git, gh | PR opened with description + test plan |
| jira-scribe | light | Jira read/write | Ticket drafts; creates only after confirm |

### 7.3 Canonical format

Each `agents/<name>.md` has frontmatter: `name`, `description`, `tier`, `tools`, `output`. `scripts/gen-agents` converts these into Claude Code (`~/.claude/agents/*.md`, tier → model field) and Codex format. Edits happen only in `agents/`.

### 7.4 delegation.md

- **Delegate:** parallelizable work, read-heavy exploration, log/k8s scanning, reviews needing fresh eyes.
- **Don't delegate:** small edits, anything depending on the current conversation's reasoning.
- Subagents return ≤ 15-line summaries; detail goes to `handoff/`.

## 8. Handoff protocol

`handoff/` is the single source of truth for multi-agent work (Claude ↔ Codex ↔ Copilot).

- Path: `handoff/<project>/<YYYY-MM-DD>-<topic>.md`
- `handoff/<project>/LATEST.md` points to the active note.
- Written and read only via the `/handoff` skill so the format never drifts.

```markdown
---
from: claude-opus-5.5
to: codex-sol
status: open        # open | claimed | done
branch: agent/claude-auth-refactor
commit: a1b2c3d
---
## Goal
## Done
## Next (ordered)
## Blockers / decisions needed
## Files touched
## How to verify
```

Rules:

1. Writer runs `/handoff` before ending a session or hitting a limit. ≤ 60 lines.
2. Receiver reads `LATEST.md`, checks it against `git diff`, sets `status: claimed`.
3. One branch per agent (`agent/<tool>-<topic>`); two agents never edit the same files at once.
4. Monthly: move `done` notes into `handoff/<project>/archive/`.

## 9. Per-repo files

`scripts/new-project` creates these in a repo (skips any that exist):

| File | Purpose | Maintained by |
| --- | --- | --- |
| `AGENTS.md` | Build/test/lint commands first, then conventions and pitfalls. ≤ 100 lines. | You + agents |
| `CLAUDE.md` | `@AGENTS.md` | Generated |
| `SPEC.md` | What's being built, acceptance criteria | Planner drafts, you approve |
| `CHANGELOG.md` | Generated from conventional commits | Script |
| `DECISIONS.md` (optional) | One line per decision: date, decision, reason | Agents append |

No per-repo `handout.md`; handoffs are central.

## 10. Token efficiency rules (docs/token-rules.md, summarized in AGENTS.md)

- **Budgets:** root and repo AGENTS.md ≤ 100 lines. Detail in `docs/`, linked as "for X, read docs/x.md".
- **Scripts over prose:** mechanical steps live in `scripts/`; output ≤ 50 lines, `--full` for raw.
- **Index before exploring:** agents read `~/dev/REPOS.md` first.
- **Delegate reading:** exploration runs in a light-tier read-only subagent; only conclusions return.
- **Fresh sessions:** one session per task; carry state with `/handoff`.
- **Short skill descriptions:** one sentence each.
- **Prune monthly:** remove or merge anything unused.

## 11. Growing it over time

`docs/adding-things.md` defines how to add each kind of thing so growth stays tidy:

- **Alias/function:** add to the themed `shell/*.zsh` file with a `# desc:` comment on the line above (the `aliases` command reads these).
- **Script:** `scripts/<name>`, executable, `set -euo pipefail`, `--help`, summary output. Passes `shellcheck`.
- **Skill:** always via `/create-skill`.
- **Agent:** always via `/create-agent`.
- **Company-specific anything:** name it with `-<COMPANY_TAG>` and put it in `company/`, `shell/local.zsh` or `me/context.md`, never in the tracked files.

Harvest rule: when something built at work proves generic, rewrite it clean on a personal machine and commit upstream. Never copy company code or text.

## 12. Setting it up at a new company

1. `cd ~/dev && git clone https://github.com/MrBenC88/0a-ancestor.git`
2. `cd 0a-ancestor && git remote rename origin upstream` — never push from the work machine.
3. `./bootstrap.sh --brew`, then `./bootstrap.sh --check`.
4. Enter a short company tag when prompted. Open a new shell, then run `gtd` and `aliases` to confirm.
5. Check the company's AI policy: approved tools, and whether code/docs may go into agent context. Adjust shims.
6. Fill `me/context.md` and `me/onboarding.md` during week one.
7. Keep `~/dev` out of personal cloud sync.

## 13. Implementation plan (for Claude Code)

Build in phases; each phase ends with its checks passing and a commit.

| Phase | Deliverables | Done when |
| --- | --- | --- |
| 1. Skeleton | Layout, `.gitignore`, README, root AGENTS.md + CLAUDE.md, templates, `me/` templates | `git status` shows no real data files tracked; AGENTS.md ≤ 100 lines |
| 2. Bootstrap | `bootstrap.sh` with `--check`, `--dry-run`, `--brew`; Brewfile | Runs twice with no changes on 2nd run; `--check` reports all green |
| 3. Shell | `shell/*.zsh`, `gpa`, `gst-all`, `gclean`, `aliases` command | `shellcheck` clean; `gpa --dry-run` correct on a dirty, a diverged and a clean repo; startup < 50 ms added |
| 4. Skills | Generalize rule in AGENTS.md; `create-skill` and `create-agent` first, then the other starter skills | Each has frontmatter + Output section, ≤ 150 lines; a test `-<company-tag>` skill lands in `company/` and `git status` doesn't show it |
| 5. Agents | 8 agents, `models.md`, `gen-agents`, `delegation.md` | `gen-agents` produces valid Claude + Codex files from `agents/` and `company/agents/` |
| 6. Repo tools | `new-project`, `index-repos`, `k8s-summary`, `logs-errors` | `new-project` is idempotent; `index-repos` writes REPOS.md for all repos |

Constraints for all phases:

- macOS + zsh first; scripts are bash with `set -euo pipefail` and must not break on Linux.
- No network calls in shell startup.
- Nothing destructive without `--dry-run` support and a confirm prompt.
- No company names, URLs or credentials anywhere in tracked files. Examples and docs always use the placeholder `<company-tag>`, never a real tag. The real value lives only in `shell/local.zsh` and `me/context.md`.
- Add a pre-commit hook (installed by bootstrap) that blocks a commit if any staged file contains the configured `COMPANY_TAG` or a hostname listed in `local.zsh`.
